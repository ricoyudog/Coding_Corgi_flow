# CorgiSpec 4.0.0-rc1

CorgiSpec 4.0.0-rc1 is the release candidate for the one-step RFC-first cutover. Features now begin with a human-authored RFC and an accepted, merged Slice; narrowly defined maintenance work uses a recorded exemption. Every delivery follows Apply → whole-change Verify → Human Review → Human QA → Archive. Validate this candidate before promoting the final `4.0.0` release.

## Upgrade

Finish, archive, or withdraw every active v3 Change and nonterminal Run Contract v2 run, then inspect the transaction without writing:

```bash
corgispec bootstrap --migrate-v4 --dry-run --json
```

Run the explicit migration after resolving every blocker:

```bash
corgispec bootstrap --migrate-v4 --yes --json
```

Migration preserves existing Memory, Wiki, `wiki/sessions/`, and `wiki/log.md`. Legacy sessions and log files become read-only history. It creates a draft `RFC-0001-project-foundation`; no delivery may be proposed until a human completes, accepts, commits, and merges that RFC into the configured integration branch.

## New delivery entry

```bash
corgispec rfc new data-export
# Human completes, validates, accepts, commits, and merges the RFC.
corgispec propose export-csv --from RFC-0002-data-export/S-01-csv --json
```

Feature prose without an accepted Slice is rejected. Maintenance proposals must fit one closed exemption category and still receive source, traceability, evidence, and the full quality chain.

## Breaking changes

- Memory and Wiki are mandatory; `--no-memory` no longer exists.
- Public Apply uses Run Contract v3 and stops at `awaiting_verify`.
- Verify, Human Review, Human QA, and Archive are distinct canonical gates.
- Active v2 runs are not migrated. Retained v2 files are legacy history; v4 exposes no Loop or Converge compatibility command.
- Project `init` and `install` no longer bypass transactional bootstrap.
