# corgispec v3.0.0-rc.3 — OpenCode Runtime Hook Launcher Fix

CorgiSpec 3.0.0-rc.3 fixes generated lifecycle hooks under the standalone OpenCode runtime. It is published to npm under the `next` dist-tag; the stable `latest` dist-tag remains on `2.4.3`.

## Install

```bash
npm install -g @fission-ai/openspec@^1.6.0
npm install -g corgispec@next
```

For a reproducible install, use `npm install -g corgispec@3.0.0-rc.3`.

Runtime requirements remain unchanged:

- Node.js >=20.19.0
- OpenSpec CLI >=1.6.0 <2.0.0

## What changed

- OpenCode plugins now capture the Node executable when CorgiSpec generates them instead of reading `process.execPath` from the standalone OpenCode host.
- A normal `session.idle` check with no active Run Contract returns silently instead of launching OpenCode with Corgi hook arguments, printing its help banner, and injecting a false failure prompt.
- Active loop continuation, hook output forwarding, exit codes, timeouts, prompt reset, and per-session activation behavior are unchanged.

## Upgrade

Upgrade CorgiSpec, refresh managed assets, and explicitly regenerate any installed OpenCode lifecycle plugin:

```bash
npm install -g corgispec@3.0.0-rc.3
corgispec bootstrap --target /path/to/project --mode update
corgispec hooks generate --platform opencode \
  --output /path/to/project/.opencode/plugins/corgispec.ts --force
```

Use `--force` only for a recognized generated plugin whose local content has been preserved or approved. Restart OpenCode after regeneration so the running process does not retain the old plugin module. Existing OpenSpec changes, loop state, schemas, and tracker configuration do not require migration.
