# corgispec v3.0.0-rc.4 — Safe Bootstrap Migration and Self-Repair

CorgiSpec 3.0.0-rc.4 upgrades `bootstrap` from a one-way installer into a complete, safety-first migration and repair pass for the selected managed surface. It is published to npm under the `next` dist-tag; stable `latest` remains on `2.4.3`.

## Install

```bash
npm install -g @fission-ai/openspec@^1.6.0
npm install -g corgispec@next
corgispec bootstrap --target /path/to/project --mode update
```

For a reproducible install, use `npm install -g corgispec@3.0.0-rc.4`.

Runtime requirements remain unchanged:

- Node.js >=20.19.0
- OpenSpec CLI >=1.6.0 <2.0.0

## What changed

- `bootstrap --mode auto|update` scans project commands/schema/config/manifest, existing hooks, user-level skills, Claude/OpenCode user commands, and known obsolete Corgi assets before any managed write.
- Manifest v2 preserves the original installation timestamp and records the package version, project hashes, platform hook ownership, generator formats, and the latest structured migration result. Legacy v1 JSON/YAML installations converge on one canonical `.corgi-install.json`.
- Missing managed files are restored automatically. Local edits, malformed structured files, and ambiguous ownership are backed up and stop the operation before local or global assets are partially updated.
- Existing Claude Code, OpenCode, and Codex hooks migrate through shared generators while preserving unrelated settings and hooks. Hookless projects remain opt-in.
- Global bootstrap now synchronizes all 29 skills for all three platforms plus all bundled Claude/OpenCode user commands. `doctor` checks hook health independently per platform.
- A filesystem transaction rolls back every touched managed path if a later write fails. A second bootstrap is idempotent.

## Backup locations

- Project: `openspec/.corgi-backups/<timestamp>/project/`
- User-level: `~/.corgispec/backups/<timestamp>/<platform>/`

Review and resolve a reported conflict before rerunning bootstrap; do not force-overwrite a backup.
