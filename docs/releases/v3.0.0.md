# CorgiSpec 3.0.0

CorgiSpec 3.0.0 promotes the RC.1–RC.8 delivery to the stable npm release channels. It keeps the tested RC8 behavior while making the unqualified package, `latest`, and `next` resolve to the same stable version.

## Install

```bash
npm install -g @fission-ai/openspec@^1.6.0
npm install -g corgispec
corgispec doctor --path /path/to/project
```

Runtime requirements:

- Node.js >=20.19.0
- OpenSpec CLI >=1.6.0 <2.0.0

## Highlights

- OpenSpec 1.6-aware planning, strict readiness checks, custom schema support, and store-aware `update`, `ready`, and `converge` commands.
- Run Contract v2 adds durable, retry-safe loop state, evidence binding, recovery, and explicit tracker checkpoints for GitHub and GitLab.
- Managed bootstrap updates now preflight the complete selected surface, preserve unrelated local configuration, back up conflicts, and migrate only Corgi-owned assets for Claude Code, OpenCode, and Codex.
- Tracked changes use a single Issue dashboard. Lifecycle commands and loops retain explicit, idempotent tracker-write boundaries.

## Breaking changes and migration

1. Upgrade Node and OpenSpec before installing CorgiSpec 3.0.0.
2. GitHub- and GitLab-tracked changes must use the single `issue` tracker object; the former `parent`/`groups` structure is rejected and must be converted manually.
3. Run `corgispec doctor` and `corgispec ready <change> --strict` for every active change after upgrading.
4. Active RC7 Run Contract state is not migrated. Start a new loop run instead of replaying its prior Task Group progress.

## Verification

The stable publishing workflow installs from the lockfile, runs `npm run release:check`, publishes an immutable tarball with npm provenance, verifies both public dist-tags, and creates this GitHub Release from the matching immutable tag.
