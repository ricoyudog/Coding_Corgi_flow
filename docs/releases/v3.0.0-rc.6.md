# CorgiSpec 3.0.0-rc.6 — Propose/Apply Handoff Boundary

CorgiSpec 3.0.0-rc.6 restores the explicit boundary between planning and implementation. Propose now completes and reports the planning package, then ends the current turn; implementation starts only after a later explicit apply or loop request. It is published to npm under the `next` dist-tag, while stable `latest` remains on `2.4.3`.

## Install

```bash
npm install -g @fission-ai/openspec@^1.6.0
npm install -g corgispec@3.0.0-rc.6
corgispec bootstrap --target /path/to/project --mode update --scope both
```

Runtime requirements remain unchanged:

- Node.js >=20.19.0
- OpenSpec CLI >=1.6.0 <2.0.0

## What changed

- GitHub, GitLab, and trackerless propose skills now state that propose is planning-only and terminal for the current turn.
- A strict `ready` result confirms planning integrity but is not user approval to implement.
- An initial request phrased as a fix, implementation, or build supplies planning intent only. The agent must wait for a later explicit apply or loop request before editing implementation files.
- Propose keeps `HEAD` unchanged and cannot install packages, create housekeeping commits, push, open implementation pull requests, or publish while preparing the planning handoff.
- OpenCode and Claude command wrappers repeat the handoff boundary, while Codex consumes the same canonical contract from the packaged skills.
- Propose uses a visible planning checklist when the host exposes an available and permitted planning or TODO mechanism, without hard-coding a platform-specific tool.

No CLI flags, schemas, hooks, tracker formats, Run Contract formats, or public TypeScript APIs changed.
