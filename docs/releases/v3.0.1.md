# CorgiSpec 3.0.1 — Unified Apply with Per-Group Commits

CorgiSpec 3.0.1 makes `corgi-apply` the sole user-facing implementation workflow. Apply now drives the existing Run Contract v2 loop engine across every Task Group, so users invoke apply once instead of repeating a separate apply command for each group.

## Install

```bash
npm install -g corgispec@3.0.1
corgispec bootstrap --target /path/to/project --mode update
```

Runtime requirements remain Node.js >=20.19.0 and OpenSpec CLI >=1.6.0 <2.0.0.

## Workflow changes

- Use `/corgi-apply`, `/corgi:apply`, or `$corgispec-apply` after approving a proposal.
- Every approved Task Group receives one dedicated commit. Run Contract v2 verifies and acknowledges that commit before tracker synchronization or the next group.
- `/corgi-loop`, `/corgi:loop`, and `corgispec-loop` are no longer packaged as user entry points.
- The old provider-specific `corgispec-apply-change` and `corgispec-gh-apply` skills remain retired.
- The hidden `corgispec apply` read-only query and hidden `corgispec loop ...` state-machine API remain internal implementation details.

## Managed upgrade safety

`corgispec bootstrap --mode update` removes retired loop commands only when their Corgi signatures match, and removes retired loop/provider-specific apply skills only when their Corgi identity is present. Same-path custom content is reported as a conflict instead of being deleted.

Unified apply does not introduce automatic push behavior. Push remains governed by an explicitly configured Run Contract policy.
