# corgispec v3.0.0-rc.2 — Invocation-Scoped Hook Enforcement

CorgiSpec 3.0.0-rc.2 fixes hook activation scope so installing Corgi hooks does not impose worktree-write or Task Group Stop enforcement on unrelated sessions. It is published to npm under the `next` dist-tag; the stable `latest` dist-tag remains on `2.4.3`.

## Install

```bash
npm install -g @fission-ai/openspec@^1.6.0
npm install -g corgispec@next
```

For a reproducible install, use `npm install -g corgispec@3.0.0-rc.2`.

Runtime requirements remain unchanged:

- Node.js >=20.19.0
- OpenSpec CLI >=1.6.0 <2.0.0

## What changed

- Claude Code applies worktree-write enforcement only while a Corgi lifecycle skill is active and applies Task Group Stop enforcement only during apply skills.
- OpenCode activates guards for matching Corgi commands or skill tools, keeps that state isolated per session, and resets activation for each new user message.
- Codex keeps destructive-command protection, non-blocking validation, and session-bound loop enforcement, but omits generic write and Stop guards because it has no documented skill lifecycle activation event.
- `stop-check` permits a checkpoint stop after one Task Group is complete when the next group is untouched. A partially completed current group still blocks stopping.

Together these changes preserve Corgi workflow safety without redirecting ordinary edits in the main checkout or blocking unrelated sessions from ending.

## Upgrade

Upgrade `corgispec`, then regenerate the managed hooks for each installed platform so the invocation-scoped configuration replaces the RC.1 project-wide guards:

```bash
npm install -g corgispec@3.0.0-rc.2
corgispec bootstrap --target /path/to/project --mode auto
```

Existing OpenSpec changes, loop state, schemas, and tracker configuration do not require migration.
