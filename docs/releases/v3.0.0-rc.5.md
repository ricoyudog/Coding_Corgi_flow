# CorgiSpec 3.0.0-rc.5 — Inactive Legacy Loop Hook Fix

CorgiSpec 3.0.0-rc.5 prevents completed legacy v1 loop records from producing false `contract_error` continuation prompts after their OpenSpec changes have been archived. It is published to npm under the `next` dist-tag; stable `latest` remains on `2.4.3`.

## Install

```bash
npm install -g @fission-ai/openspec@^1.6.0
npm install -g corgispec@3.0.0-rc.5
corgispec bootstrap --target /path/to/project --mode update --scope both
```

Runtime requirements remain unchanged:

- Node.js >=20.19.0
- OpenSpec CLI >=1.6.0 <2.0.0

## What changed

- A single valid legacy run with `active: false` is treated as historical state. `hook loop-check` returns `proceed` / `idle` without requiring the archived planning change or migrating legacy files.
- Active or ambiguous legacy runs still use canonical inspection and migration. Corrupt JSON, future schemas, symlinked paths, and non-regular state files continue to fail closed.
- Canonical run discovery rejects visible symlink and non-directory run entries, so canonical corruption cannot be hidden by an inactive legacy record.

No CLI flags, schemas, Run Contract formats, or public TypeScript APIs changed.
