# CorgiSpec 3.0.0-rc.8 — Loop Tracker Checkpoints

CorgiSpec 3.0.0-rc.8 makes per-Task-Group tracker progress an explicit loop checkpoint for GitHub- and GitLab-tracked changes. The prerelease is published to npm under the `next` dist-tag; stable `latest` remains on `2.4.3`.

## Install

```bash
npm install -g @fission-ai/openspec@^1.6.0
npm install -g corgispec@3.0.0-rc.8
corgispec bootstrap --target /path/to/project --mode update --scope both
```

Runtime requirements remain unchanged:

- Node.js >=20.19.0
- OpenSpec CLI >=1.6.0 <2.0.0

## What changed

- After `corgispec loop ack-commit`, a GitHub- or GitLab-tracked loop enters `awaiting_tracker_sync`. It does not advance to the next Task Group until `corgispec loop sync-tracker` records the current committed group on its configured Issue.
- `sync-tracker` derives its target from the change's `.github.yaml` or `.gitlab.yaml` Issue URL, never from the current git remote. GitHub uses `gh`; GitLab uses `glab`.
- The checkpoint replaces only CorgiSpec's marked Task Dashboard region and adds a marked Task Group comment. Before writing, it recognizes an existing matching marker, so a retry after an interrupted successful remote request does not duplicate the comment.
- Trackerless changes and changes without a tracker binding remain local-only. No command writes to a tracker unless an active loop is explicitly advanced with `sync-tracker`.
- Loop hooks can report `sync_tracker` as the next action, but do not call `gh` or `glab`. Codex, Claude Code, and OpenCode loop skills are explicit-only, so ordinary skills, manual `tasks.md` edits, and host Stop/idle events cannot accidentally update an Issue.
- While a loop is active, other tracker-writing lifecycle workflows for that same change defer to the loop checkpoint. Other changes in the repository are unaffected.

## RC7 compatibility

This release does not migrate active RC7 loop state. Do not resume an RC7 run after upgrading if its next operation would require a tracker checkpoint; begin a new RC8 loop run instead. Existing remote Issue content is not automatically replayed or rewritten.

## Verification

- Automated coverage exercises GitHub, GitLab, and trackerless runs; commit-to-sync ordering; retry idempotency; marker preservation; and lifecycle mutual exclusion.
- Codex, Claude Code, and OpenCode fixtures verify that hooks only surface actions and that explicit loop invocation remains available without implicit tracker writes.
- The release gate installs from the lockfile, runs the complete test/coverage/skill/mirror suite, audits production dependencies, and installs the packed tarball in isolation.
