# CorgiSpec 3.0.0-rc.7 — Single Issue Tracking

CorgiSpec 3.0.0-rc.7 changes GitHub and GitLab change tracking to use one Issue per change. The prerelease is published to npm under the `next` dist-tag; stable `latest` remains on `2.4.3`.

## Install

```bash
npm install -g @fission-ai/openspec@^1.6.0
npm install -g corgispec@3.0.0-rc.7
corgispec bootstrap --target /path/to/project --mode update --scope both
```

Runtime requirements remain unchanged:

- Node.js >=20.19.0
- OpenSpec CLI >=1.6.0 <2.0.0

## What changed

- GitHub- and GitLab-tracked propose workflows create one Issue for each change, rather than a parent Issue plus one child Issue per Task Group.
- The authoritative task artifact drives a managed Task Dashboard in the Issue body. Apply and review refresh its task checkboxes, group status, and progress; verify, review evidence, Human QA, blockers, and archive history are Group-scoped comments on that same Issue.
- Task Groups still gate implementation, verification, and review one group at a time. The tracker representation changed, not the task parser, Run Contract v2, loop/update/converge state machines, CLI flags, or public TypeScript APIs.
- GitHub uses `backlog`, `in-progress`, `review`, `todo`, and `done`; GitLab uses the matching `workflow::*` labels. Final Issue closure retains each platform's existing archive policy.

## Breaking tracker migration

- New tracking files contain only `issue.number` / `issue.url` for GitHub or `issue.iid` / `issue.url` for GitLab.
- Existing `parent` / `groups` tracking files fail before local implementation or remote writes. To continue an old change, retain the former parent as its single Issue, rewrite the tracking YAML to the new `issue` object, and manually close or retain former child Issues. CorgiSpec does not migrate or modify child Issues automatically.
- The dashboard rewrites only its marked managed region. If the region is missing or malformed, synchronization stops without overwriting the rest of the Issue body. Manual checkbox changes are display-only and are replaced by the authoritative task artifact on the next synchronization.

- A disposable three-Task-Group fake GitHub and GitLab walkthrough confirmed exactly one Issue creation and one continuing Issue ID through apply, verify, review/reject-repair, QA, and archive; it also verified dashboard label/progress behavior, legacy rejection before mutation, and preservation of unmanaged Issue content.
- The complete Node 20.19+ release gate passed: 1,037 tests passed, one platform-specific test skipped, coverage remained 91.44% statements, 87.99% branches, 94.72% functions, and 92.34% lines; 29 skills, 87 mirrors, the production audit, and the package smoke test all passed.
