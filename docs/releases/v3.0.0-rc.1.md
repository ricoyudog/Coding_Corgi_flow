# corgispec v3.0.0-rc.1 — OpenSpec 1.6 Planning Integrity + Run Contract v2

CorgiSpec 3.0.0-rc.1 is the first release candidate for the OpenSpec 1.6 planning contract and the crash-recoverable Run Contract v2. It is published to npm under the `next` dist-tag; the stable `latest` dist-tag remains on `2.4.3`.

## Install

```bash
npm install -g @fission-ai/openspec@^1.6.0
npm install -g corgispec@next
```

For a reproducible install, use `npm install -g corgispec@3.0.0-rc.1`.

Runtime requirements:

- Node.js >=20.19.0
- OpenSpec CLI >=1.6.0 <2.0.0
- OpenSpec 1.3–1.5 are not supported as a fallback

Run `corgispec doctor --path /path/to/project` after upgrading. Existing changes should also pass `corgispec ready <change> --strict --json` before apply or loop.

## Highlights

- OpenSpec JSON is now authoritative for the planning home, change root, artifact DAG, glob-expanded artifact paths, status, and instructions. Custom schema names and OpenSpec Stores are supported without Corgi guessing `tasks.md`, `specs/`, or a change directory.
- `corgispec update <change> --json` returns read-only planning coordination context, while `corgispec ready <change> --strict --json` provides a deterministic planning-integrity preflight.
- Tracker selection is independent from schema selection through `corgi.tracking.provider`; `corgi.taskArtifactId` selects the schema's executable task artifact.
- Run Contract v2 makes `corgispec loop init|inspect|submit|ack-commit|finalize|invalidate|resume` the only canonical lifecycle writer. Per-change locking, CAS tokens, durable event logs, replay, atomic bundles, and evidence binding make interrupted runs recoverable and stale writes fail closed.
- `corgispec converge <change> --json` reports `converged`, `needs_work`, or `blocked`. A confirmed implementation-only gap appends one successor Task Group without rewriting old groups.
- Claude Code, OpenCode, and Codex commands/skills are bundled for update, ready, loop, and converge. Codex hooks use TOML plus Node `.cjs` wrappers.

OpenCode 1.18.x does not provide an awaited stop hook. The generated plugin observes `session.idle`, preserves hook stdout/stderr, and uses `session.promptAsync` to resume an interactive session when work remains. `corgispec ready` and canonical `corgispec loop ...` state remain the hard gates; one-shot `opencode run` automation should inspect those CLI results because teardown can race asynchronous re-entry.
