# Corgispec Hooks Migration to OpenCode Plugin

## TL;DR

> **Quick Summary**: Fix `corgispec hooks generate --platform opencode` to output a valid OpenCode TypeScript plugin instead of the deprecated Claude Code bridge JSON (`{ hooks: { ... } }`) that OpenCode v1.17.7+ rejects.
>
> **Deliverables**:
> - Rewritten `generateOpenCodeOutput()` that produces a TypeScript plugin by default
> - Expanded `buildOpenCodeDeepPlugin()` registering all 6 Corgispec hooks via OpenCode plugin API
> - Stdin→plugin-API translation layer for `pre-write`, `pre-bash`, `post-write`
> - Updated tests (TDD), CLI help text, and install tips
> - `detectHookConfig()` path/name coupling preserved
>
> **Estimated Effort**: Medium
> **Parallel Execution**: YES — 4 waves
> **Critical Path**: Task 1 → Task 5 → Task 8 → Task 17 → F1-F4

## Context

### Original Request
OpenCode v1.17.7 rejects the `hooks` key in `~/.config/opencode/opencode.json`. The config schema (`https://opencode.ai/config.json`) has `"additionalProperties": false` and `hooks` is not a recognized key. Root cause: Corgispec's `corgispec hooks generate --platform opencode` outputs Claude Code bridge JSON (`{ hooks: { ... } }`) which was valid under an older OpenCode version but not v1.17.7+. Fix: generate an OpenCode TypeScript plugin instead.

### Interview Summary
**Key Discussions**:
- Plugin distribution: Local plugin (`.opencode/plugins/corgispec-deep.ts`) generated by `corgispec hooks generate`
- Backward compatibility: Dropped (old OpenCode ignores `.opencode/plugins/` directory)
- Phased approach: 4 waves of increasing complexity to manage risk
- Plugin path/name: Keep existing `.opencode/plugins/corgispec-deep.ts` and `CorgiSpecDeep` (locked by `detectHookConfig()` in hooks.ts:357-362)
- `--deep` flag: Deprecated (becomes no-op alias since plugin is now default)
- `buildClaudeConfig()`: Frozen (still used by `--platform claude`)

**Research Findings**:
- OpenCode plugin API supports: `tool.execute.before`, `tool.execute.after`, event subscriptions (`session.created`, `session.compacted`, `session.idle`, etc.)
- Existing `buildOpenCodeDeepPlugin()` (generate.ts:240-265) only implements `experimental.chat.system.transform` for session-start
- CLI hooks (`pre-write`, `pre-bash`, etc.) expect JSON on stdin — need translation layer from plugin function args
- `detectHookConfig()` at hooks.ts:337-373 checks for `.opencode/plugins/corgispec-deep.ts` containing `CorgiSpecDeep`

### Metis Review
**Identified Gaps** (addressed):
- Stdin→plugin translation layer: Added as dedicated task in Wave 2
- `session.idle` contradiction: Deferred to Wave 3 with empirical validation task
- Plugin path inconsistency: Resolved — keep existing path/name to preserve detection coupling
- Product questions (`--deep` flag, version detection): Resolved — deprecate `--deep`, drop version detection
- Phasing recommendation: Adopted — 4 waves

## Work Objectives

### Core Objective
Replace `generateOpenCodeOutput()`'s Claude Code bridge JSON output with an expanded TypeScript plugin that registers all Corgispec lifecycle hooks using OpenCode's plugin API, delivered incrementally over 4 waves.

### Concrete Deliverables
- Rewritten `generateOpenCodeOutput()` in `packages/corgispec/src/commands/hooks/generate.ts`
- Expanded `buildOpenCodeDeepPlugin()` generating a TypeScript plugin covering all 6 hook events
- Updated tests in `packages/corgispec/test/hooks/generate.test.ts` (TDD: RED → GREEN)
- Updated CLI help text in `packages/corgispec/src/commands/hooks/generate.ts`
- Updated install tip in `packages/corgispec/src/commands/install.ts`

### Definition of Done
- [ ] `corgispec hooks generate --platform opencode` outputs TypeScript (not JSON)
- [ ] Generated plugin loads in Bun without type errors: `bun build .opencode/plugins/corgispec-deep.ts --no-bundle`
- [ ] `detectHookConfig()` returns `platform: "opencode"` with new plugin
- [ ] All existing tests pass: `npx vitest run test/hooks/generate.test.ts`
- [ ] `corgispec hooks generate --platform claude` unchanged (Claude output regression check)

### Must Have
- Plugin becomes default OpenCode output (TypeScript, not Claude JSON)
- SessionStart hook: injects project context via `experimental.chat.system.transform`
- PreToolUse hooks (pre-write, pre-bash): block on `tool.execute.before` with stdin translation
- PostToolUse hook (post-write): async post-execution via `tool.execute.after`
- Stop hooks (stop-check, loop-check): fire on session end via event subscription
- PostCompact hook (post-compact): fire after context compaction via `session.compacted` event
- Detection coupling preserved: path `.opencode/plugins/corgispec-deep.ts`, name `CorgiSpecDeep`

### Must NOT Have (Guardrails)
- MUST NOT modify `buildClaudeConfig()` — shared with `--platform claude`
- MUST NOT modify runtime CLI hook commands (`session-start.ts`, `pre-write.ts`, `pre-bash.ts`, `post-write.ts`, `post-compact.ts`, `stop-check.ts`, `loop-check.ts`)
- MUST NOT add `@opencode-ai/plugin` as dependency in `packages/corgispec/package.json`
- MUST NOT change plugin detection path or name in `hooks.ts:357-362`
- MUST NOT add version detection infrastructure
- MUST NOT implement migration tooling for old opencode.json configs
- `experimental.chat.system.transform`: catch and silently skip errors (non-blocking)
- `tool.execute.before`: throw only for matching tools (intentional blocking)
- execSync timeouts: ≤5s for blocking hooks, ≤10s for async hooks
